A — `product_id` товаров, купленных клиентами из MT, B — из MS.
Только заказы `delivered`. A и B оформлены представлениями

## Мощности

| Множество | Строк (`count(*)`) | Различных `product_id` |
|---|---|---|
| A (MT) | 1 037 | 841 |
| B (MS) | 811 | 647 |
| A ∪ B, `UNION` | 1 395 | 1 395 |
| A ∪ B, `UNION ALL` | 1 848 | — |
| A ∩ B, `INTERSECT` | 93 | 93 |
| A − B, `EXCEPT` | 748 | 748 |
| B − A, `EXCEPT` | 554 | 554 |

Проверка: 841 + 647 − 93 = 1 395, 748 + 93 = 841, 554 + 93 = 647.

- `A ∪ B = B ∪ A` и `A ∩ B = B ∩ A`: симметрическая разность пуста.
- `A − B ≠ B − A`: 748 и 554 разных товаров, общих нет.
- Пересечение через `EXISTS` с `DISTINCT` даёт те же 93 товара.

## Дубликаты

A и B — мультимножества: товар повторяется столько раз, сколько его
покупали (1 037 строк на 841 товар в MT). `UNION ALL` даёт 1 848 = 1 037 + 811
строк, `UNION` — 1 395 различных товаров.

Пересечение через `EXISTS` без `DISTINCT` вернуло 149 строк вместо 93:
некоторые товары повторяются до 6 раз. `INTERSECT ALL` даёт 120 строк
(min(m, n) для каждого товара), `EXCEPT ALL` — 917.

Множество возвращают `UNION`, `INTERSECT`, `EXCEPT`, `SELECT DISTINCT`.
Мультимножество могут вернуть `UNION ALL`, `INTERSECT ALL`, `EXCEPT ALL`,
обычный `SELECT`, `JOIN`, `EXISTS`/`IN` без `DISTINCT`.

## Контрольные вопросы

**Почему UNION обычно дороже UNION ALL?**
`UNION ALL` просто выдаёт строки обоих запросов подряд. `UNION` должен
удалить дубликаты, для этого строки сортируются или кладутся в хеш-таблицу.
Это лишняя память и время, особенно на больших данных.

**Почему без ORDER BY нельзя делать вывод о «порядке» кортежей?**
Отношение — множество, порядка у него нет. Без `ORDER BY` СУБД отдаёт строки
в том порядке, в каком ей удобно: зависит от плана, способа соединения,
физического расположения строк. После обновления данных или смены плана
порядок может стать другим.

**Чем множество отличается от мультимножества?**
В множестве каждый элемент встречается один раз. В мультимножестве элемент
может повторяться, и важно, сколько раз. SQL-таблицы и результаты запросов —
мультимножества, пока не используются `DISTINCT` или `UNION`/`INTERSECT`/`EXCEPT`
без `ALL`.
