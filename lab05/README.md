## Результаты

| Решение | Категорий |
|---|---|
| двойной `NOT EXISTS` | 47 |
| `GROUP BY / HAVING COUNT(DISTINCT state)` | 47 |
| `EXCEPT` + `NOT EXISTS` | 47 |

Всего категорий с продажами — 73. `EXCEPT` между решениями в обе стороны
даёт 0 строк, значит, все три решения дают одно и то же множество.

Пример: `beleza_saude` — GO 206 заказов, MS 57, MT 83. Категория
`climatizacao` есть в GO и MT, но не в MS, поэтому в результат не попала.

Пустой `target_states`:

| Решение | Категорий |
|---|---|
| двойной `NOT EXISTS` | 73 (все) |
| `EXCEPT` + `NOT EXISTS` | 73 (все) |
| `HAVING COUNT` | 0 |

«Для всех s из пустого множества» — всегда истина, поэтому правильный ответ —
все категории. Так работают `NOT EXISTS` и `EXCEPT`. В `HAVING` после JOIN
с пустым делителем не остаётся строк и групп, поэтому результат пустой.

Дополнительно: продавцов, которые продавали покупателям всех трёх штатов, — 163.

## Контрольные вопросы

**Как переписать «для всех x выполняется P(x)» через «не существует»?**
∀x P(x) ≡ ¬∃x ¬P(x): не существует x, для которого P не выполняется.
В SQL: `NOT EXISTS (… WHERE NOT EXISTS (…))` — нет такого штата из S, в
котором категория не продавалась.

**Почему COUNT(DISTINCT state) сравнивают с мощностью делителя?**
Категория должна быть во всех штатах из S. После JOIN с S остаются только
штаты из S. Если различных штатов столько же, сколько в S, значит, есть
каждый. DISTINCT нужен, потому что в одном штате много продаж. Сравнивать
надо с `count(*)` из делителя, а не с константой 3, чтобы запрос был верен
при любом S.

**Что происходит с универсальным условием, если множество пусто?**
Оно истинно для любого объекта: нет ни одного элемента, на котором оно
могло бы нарушиться. Поэтому деление на пустое множество возвращает все
объекты. Решения через `NOT EXISTS` так и работают, а `HAVING COUNT` даёт
пустой результат — его нужно проверять отдельно.
