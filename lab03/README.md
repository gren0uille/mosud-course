Отношение `G = olist.geolocation`. Условие: штат RJ и широта от −23.1 до −22.7


## Реляционное выражение

Исходное:

```
ρ_{zip_prefix, lat, lng, city} (
  π_{zip_code_prefix, lat, lng, city} (
    σ_{state = 'RJ' ∧ -23.1 ≤ lat ≤ -22.7} (G)))
```

Две выборки подряд:

```
σ_{-23.1 ≤ lat ≤ -22.7} ( σ_{state = 'RJ'} (G) )
```

С ранней проекцией (state отбрасывается сразу после фильтра по штату):

```
ρ(σ_{-23.1 ≤ lat ≤ -22.7} ( π_{zip_code_prefix, lat, lng, city} ( σ_{state = 'RJ'} (G) )))
```

## Эквивалентность и дубликаты

Все три запроса дают одинаковый результат: `EXCEPT ALL` в обе стороны вернул
0 строк, то есть совпадает и набор кортежей, и число повторов. Конъюнкцию
можно разбить на последовательные выборки, а проекцию выполнить раньше
второй выборки, потому что фильтр по широте использует только lat, а он
остаётся в проекции. В `geolocation` нет ключа, и одна точка встречается
много раз (до 102 раз), поэтому `SELECT` вернул 93 279 строк, а
`SELECT DISTINCT` — 57 599. Математическая проекция π соответствует
`SELECT DISTINCT`, обычный `SELECT` в SQL возвращает мультимножество.

## Контрольные вопросы

**Какие свойства выборки позволяют менять порядок фильтров?**
Выборка каскадна: σ_{p1 ∧ p2}(R) = σ_{p1}(σ_{p2}(R)). И коммутативна:
σ_{p1}(σ_{p2}(R)) = σ_{p2}(σ_{p1}(R)). Каждый фильтр смотрит только на
одну строку и не зависит от других, поэтому порядок фильтров на результат
не влияет.

**Почему проекция в математике убирает повторы, а SELECT — нет?**
В реляционной модели отношение — множество, в нём не бывает двух одинаковых
кортежей, и результат проекции тоже множество. SQL работает с
мультимножествами: удаление дубликатов требует сортировки или хеширования,
это дорого, и повторы иногда нужны для подсчётов. Поэтому их убирают
только явно, через `DISTINCT`.

**Что означает замкнутость операций реляционной алгебры?**
Результат любой операции — снова отношение. Значит, его можно подать на
вход следующей операции и строить выражения любой вложенности. В SQL это
подзапросы в `FROM`.
