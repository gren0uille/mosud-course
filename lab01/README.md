## Способ импорта

Использована серверная команда `COPY`. Каталог `data/olist` с девятью CSV
примонтирован в контейнер как `/data/olist` только на чтение, поэтому сервер
читает файлы напрямую.

При работе с локально установленной СУБД вместо этого применяется
клиентская команда `\copy` с путём на стороне клиента:

```
\copy olist.customers FROM '/путь/к/data/olist/olist_customers_dataset.csv' \
    WITH (FORMAT csv, HEADER true, ENCODING 'UTF8');
```

Источник данных: Brazilian E-Commerce Public Dataset by Olist, лицензия
CC BY-NC-SA 4.0.

## Порядок выполнения

```bash
docker compose up -d
docker exec -i mosud-postgres psql -U student -d olist -v ON_ERROR_STOP=1 < schema.sql
docker exec -i mosud-postgres psql -U student -d olist < check.sql
```

`schema.sql` создаёт схемы и таблицы, импортирует CSV, добавляет ключи и
выполняет `ANALYZE`. Файл выполняется повторно без ручного редактирования:
таблицы предварительно удаляются.

## Контрольные вопросы

**1. Чем база данных отличается от схемы PostgreSQL?**

База данных — отдельное хранилище со своим набором системных каталогов;
в одном подключении доступна только одна база. Схема — пространство имён
внутри базы, группирующее таблицы, представления и функции. Объекты разных
схем одной базы доступны в одном запросе через полное имя `схема.таблица`,
тогда как обращение к другой базе требует нового подключения. В работе это
использовано для разделения неизменяемых исходных данных (`olist`) и учебных
объектов (`lab`).

**2. Почему внешние ключи удобнее добавлять после массовой загрузки CSV?**

При активном внешнем ключе СУБД проверяет каждую вставляемую строку на
наличие родительской записи, что замедляет импорт. Кроме того, порядок
загрузки файлов становится критичным: дочерняя таблица не может быть
заполнена раньше родительской. Добавление ключа после импорта выполняет
проверку однократно для всего набора данных.

**3. Чем `COPY` отличается от psql-команды `\copy`?**

`COPY` выполняется сервером и читает файл в файловой системе сервера; для
этого требуются права суперпользователя или роли `pg_read_server_files`.
`\copy` — команда клиента psql: файл читается на стороне клиента, а данные
передаются серверу по протоколу подключения, особых прав не требуется.
Различие существенно при работе в Docker: путь, видимый контейнеру, и путь
на компьютере студента — разные. В этой работе каталог с CSV смонтирован в
контейнер, поэтому применима серверная `COPY`.
